DEVLOG · 2026.09.25 · RTX LIDAR / RULE-ONLY

Detect obstacles first.
Then decide where to go.

Install and calibrate RTX LiDAR, test obstacle stopping, then run six fixed layouts with one controller. Five reach the goal; the fully blocked case stops.

Previous: URDF import, differential drive and corridor collisions →

01 / MOUNT THE SENSOR

The body is in place.
Make LiDAR produce real scan data.

Add RTX LiDAR beneath base_link/base_scan in navbot_lidar_test.usda. Derive navbot_planar_lidar.usda from NVIDIA Example_Rotary and flatten references to remove online sensor-file dependencies.

One horizontal scan plane, 5 Hz, 360 nominal emission angles and a nominal 0.12–3.5 m range, without noise. An initial extra 4 cm mounting offset was removed to match URDF base_scan. This is simulator alignment, not hardware calibration.

Read Generic Model Output through LidarSensor, wait for full scans and deduplicate by frameId. Valid hits need not total 360: bin into one-degree ranges, then 36 sector minima. RTX senses visible geometry, not PhysX collision raycasts.

02 / CALIBRATE BEFORE DRIVING

Start with known positions,
check the distances it measures.

With the robot stationary, place a 0.2 m cube 1 m ahead of the LiDAR. Expected front-face range: 0.900 m; measured: 0.899998 m. Independent +90° left and −90° right targets both passed at 0.300 m.

STARTUP

From empty output to valid scans

Initial Hydra configuration mismatches produced empty output. Enable Motion BVH, use viewport tickRate=0 and synchronous rendering, then restart. The custom single-line channelId [1] worked. These startup changes were not causally isolated one by one.

NEAR RANGE

Why did the 0.3 m target disappear?

nearRangeM=0.12 alone was insufficient. minDistBetweenEchosM defaulted to 0.4; setting it to 0.01 m and reloading restored the 0.3 m side targets. Save the fix in navbot_lidar_stop_test.usda; the initial scene is not the final configuration.

VISUAL DEBUG

Robot visible only as a small red block

Poses and meshes existed but visual instances rendered incorrectly. Disable instanceable on four visual roots in the shared test layer, preserving the source robot. The red block is camera_link appearance, not LiDAR; green points are scan debugging.

03 / SCAN → STOP

Learn to stop,
then try navigating around them.

Use the nearest valid return within ±10° forward and drive at 0.08 m/s. Without the cube, travel is about 0.147 m in 2 s. Thresholds 0.60/0.45 m produce final surface ranges about 0.596/0.434 m; braking travel is below 1 mm in both.

At 5 Hz, sampling delay can put stopping distance slightly below the threshold. Code zeros velocity and reports an error after 0.6 s without a scan; no deliberate dropout test was run here.

04 / SIX FIXED CASES

It can navigate around obstacles,
and recognize when the route is blocked.

One local rule-only controller estimates passable directions from scans with a 0.17 m circular envelope. It combines clearance and goal direction, capped at 0.08 m/s and 0.6 rad/s. No obstacle coordinates are supplied; goal direction uses ground-truth pose.

Pass criteria and scope of evidence

Open layouts must reach within 0.12 m of the goal. Blocked layouts must stop for no route or 5 s without progress. Both require sampled force components ≤ 0.1 N and braking displacement < 0.03 m. Timeouts fail.

Monitor six robot rigid bodies against test obstacles and non-Floor corridor colliders. Maximum sampled force components were 0 N and braking displacements below 0.8 mm. Sampling is not a formal guarantee of continuous contact-free motion.

05 / REPLAY & RECORD

Keep the scripts,
make the experiment inspectable.

Download four actual Python scripts and setup, stop-test and navigation instructions. They depend on existing USD scenes and prim hierarchies; robot, room and full sensor assets are excluded.

Download scripts and notes

  1. 01
    STARTUP

    Start with the validated configuration

    Launch locally with launch_lidar_sync.ps1 and wait for scene/shader loading. See the download README for startup settings. Python Server supports remote execution; Script Editor does not require it.

  2. 02
    LIDAR

    Scan, then stop

    Open the initial LiDAR scene and run navbot_lidar_test.py in Script Editor. For direction and near-range checks, open navbot_lidar_stop_test.usda and run navbot_lidar_stop.py. Scripts create calibration cubes; returns to the start are resets.

  3. 03
    NAVIGATION

    Run six rounds of testing

    Save edits, then run navbot_navigation_suite.py. It switches scenes, overwrites same-named test layers and reports, and pauses when complete. See navigation-suite.md for single-case runs. Run no other controller concurrently.

  4. 04
    CAPTURE

    Generate video at simulation time

    Use Kit capture_viewport_to_file roughly every 0.2 s and log simulation time. encode_navigation_suite.py uses FFmpeg to encode 25 fps by timestamp; duplicated frames do not mean 25 Hz capture. Hold endings for about 1 s. This differs from the prior Movie Capture workflow.
